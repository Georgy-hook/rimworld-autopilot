# Сквозной путь колонии и контракт API — 2 октября 2026

## Что означает эта проверка

Проверены исходники Python, зарегистрированные маршруты C# и игровые определения
установленного RimWorld 1.6.4871 rev590. Ключевые игровые методы прочитаны через
ILSpy из установленной Assembly-CSharp.dll. Проверялись данные, доступные решения,
законные команды и наблюдение результата на переходах между этапами.

Это условный проход по коду и контрольным состояниям. Выборы в офлайн-тестах задаёт
тестовый агент; веса Laya не загружались. Выживание и победа настоящей политики
не доказаны. Игра, директор, наблюдатель и новая колония для этой работы не запускались.

На каждом этапе остаются альтернативы и откладывание. Код проверяет
исполняемость и сохраняет последствия: польза, риск, стоимость, бездействие,
неопределённость. Это не оценка вероятности победы.

## Маршруты завершения

### 1. Собственный корабль

1. Исследовательский фронт строится из действительных зависимостей игровых Def.
2. Производство и торговля видят недостающие материалы. ИИ-ядро доступно как
   конкретный товар, когда оно действительно есть у торговца; его не создаёт API.
3. План содержит три двигателя и связанный корпус с действительными размерами.
   Перед первым элементом проверяется участок. Размещаются только обеспеченные
   материалы; занятые другими заказами ресурсы вычитаются.
4. Капсулы ставятся после завершённых балок: игровой PlaceWorker требует реальное
   основание. Частичная установка не закрывает весь строительный заказ.
5. API `colony/progression` проверяет фактически соединённые части, требования
   запуска и стадию реактора. Пуск требует пережить обычную игровую эскалацию.
6. Посадка — отдельная работа Enter/CarryToCryptosleepCasket. Laya видит, сколько
   останется бойцов и врачей. Последняя севшая пешка не делает карту невидимой.
7. Запуск имеет отдельные native blockers; отсчёт не объявляется победой.
8. Завершение фиксируется только сохранённым свидетельством игровых титров.

Разрушенная часть, отсутствие материала, неуспешная работа и изменение условий
возвращают процесс к актуальному снимку. Геометрический план не гарантирует
подходящий участок на любой возможной карте.

### 2. Поход к существующему кораблю

Открытая игрой цель → фактический путь и оценка времени → выбор группы и запаса
питания/лекарств → обычный сбор каравана → сохранённое native действие прибытия →
карта корабля → реактор/оборона → посадка → запуск → подтверждение титров.

Это отдельная доктрина `ship_journey`; ей не навязываются исследования собственного
корабля. При нехватке походной еды видны рецепт, станок, Cooking 8 и исследование
MealSurvivalPack. План учитывает реальные пищевые политики всех путешественников,
массу, носимость и людей/запасы, оставленные дома. Дни запаса отделены от оценки
длительности пути. Только время, взятое из native path/rest/movement расчёта,
может использоваться как ETA; неизвестная оценка остаётся неизвестной.

### 3. Royal Ascent

Честь и native титул → подходящие трон/комнаты → условия реального предложения →
подготовка гостевых комнат и обслуживания → принятие → проживание и защита гостя →
обычное отправление шаттла → игровой сигнал завершения → титры.

Ранг берётся из установленного Def: в текущей установке внутреннее имя `Count`,
отображаемая метка `archon`. Название из справочника не заменяет native gate.
Принятое задание не означает выполненное гостеприимство. Качество мебели,
впечатляющий интерьер, питание, настроение, тепло и безопасность проверяются по
фактическому гостю и комнате; у чертежа ещё нет успешного результата.

### 4. Archonexus

Реальная стоимость/отношения/изучение текущей структуры → предложенная игрой
продажа → явный выбор переносимых людей, животных и имущества → подтверждение →
native выбор следующей клетки/идеологии → следующая колония в той же кампании →
повторение предусмотренных игрой циклов → открытый финальный участок → поход →
обычная работа активации → титры.

CampaignId сохраняет цель после замены карты. Координаты и старые заказы в новый
дом не переносятся. Поддерживаются промежутки без загруженной карты. Старое
задание спасения не может вызвать возврат с другого финального участка.

### 5. Anomaly

Видимые сущности и их исследование/содержание → требуемые открытия EntityCodex →
доступная native активация монолита → защита и действия с void nodes → явный
финальный выбор → титры.

Счётчик открытых сущностей отличается от завершённых исследований. Отказы native
float-menu и текст состояния объекта передаются как блокеры. Способность нажать
кнопку не доказывает готовность пережить событие. Скрытые диагнозы не выдаются за
знание колонии; подозрения требуют предусмотренной игрой диагностики.

### 6. Odyssey / mechhive

Загруженные определения и доступные native задания → исследование/постройка и
подготовка гравикорабля → native управление направлением/посадкой → фактические
этапы конечного задания → native взаимодействие и титры.

Код ограничен активным DLC и имеет обработчики промежуточных выборов. Здесь
отсутствует каталог Data/Odyssey. Общие игровые классы доступны для компиляции,
но полную цепочку на установленных данных Odyssey подтвердить нельзя. Этот
пункт остаётся ограничением доказательства, а не объявленной сыгранной победой.

## Исправленные разрывы контрактов

- Локальные рабочие раньше смешивались с жителями других карт и караванов.
- Смена карты могла терять цель; старое сохранение — возвращать будущие решения.
- Путь мог останавливаться без обычной карты, на временном участке или после
  посадки последнего путешественника в капсулу.
- Таймер истечения задания менялся во время выбора и отклонял ещё допустимый
  приказ. Теперь сравнивается значимое актуальное условие.
- Пустой список походов скрывал, чего не хватает; появились наблюдаемые
  потребности и связанное исследование походного пайка.
- Для Royal Ascent добавлены будущие гости, native требования комнат, варианты
  мебели и пола, исследования и назначение подходящей кровати/трона. Улучшение
  интерьера учитывает требуемую впечатляющесть выше прежнего порога 120.
- Медицинская ветка отбрасывала объект `{rooms: [...]}` как будто ожидала массив.
  Исправлена форма ответа и независимое от языка обозначение роли помещения.
- Недостающие ресурсы/цель терялись между выбором направления и рецепта.
- Старый корабельный план имел один двигатель, пересекающиеся элементы и
  пытался поставить капсулы до готовности балок.
- Произвольный лимит торгового предпросмотра скрывал дорогие покупки; конкретное
  ядро не было полноценной альтернативой. Теперь действует реальный бюджет.
- Успешный HTTP-конверт ошибочно считался успешной стройкой. Проверяются точные
  элементы и координаты; убрано отсечение наблюдаемых проектов после первых 100.
- При параметрических выборах терялись данные о корме, порче, холодильниках и
  рабочих; защищённые лечебные работы могли прерываться боевыми/служебными.
- Обычное изменение голода/текущей работы делало способность вечно устаревшей.
  Значимые клинические изменения и стоимость продолжают проверяться перед действием.
- Часть старых промптов переполняла окно модели. Теперь переполнение пакуется
  явно, выбранная цель и поля последствий сохраняются в видимом контексте.

## Границы вывода

Офлайн-проверка подтверждает наличие и согласованность перечисленных путей
управления. Она не доказывает, что обученная Laya выберет удачную последовательность,
не будет чрезмерно откладывать, выиграет бой или переживёт любой seed. Катастрофа
может физически лишить колонию ресурсов или исполнителей; API не должен отменять
правила игры ради достижения финала.

Тесты маршрутов проверяют статические прямые вызовы и HTTP-метод, а не ответы
живого сервера. Контрактные тесты проверяют типизированные JSON-примеры и свежую
валидацию. Компиляция подтверждает доступность используемых классов установленной
версии. Токенизатор подтверждает размер фактически упакованных входов, не понимание
или качество решений модели. Живой прогон остаётся отдельной будущей проверкой.
